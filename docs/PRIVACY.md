# Where project data goes

Geometry generation, STL import, material-curve interpolation, inverse search, elastic analysis, guided-drop simulation, 3MF packaging and project export run in the browser. They need no AI connection. The built app serves its application modules, workers, meshing and dynamics WASM, and examples from its origin. The optional Qwen load uses the fixed sources below. Its source contains no analytics or telemetry client. A hosted installation still receives normal HTTP requests for its files and may have infrastructure-level access logs.

| Action | Data and recipient | Retention under application control |
| --- | --- | --- |
| Open the workbench or a bundled example | The hosting service receives ordinary requests for the page, its assets and the example selected. | Hosting access-log policy belongs to the operator. |
| Import a private STL, compression CSV or project | The browser reads the selected file locally. The geometry worker receives the normalized envelope when meshing. | In memory until the page is unloaded, unless you save or export a project. |
| Save locally | The browser writes the current project to this origin's IndexedDB. A new save replaces its single current draft. | May include envelope coordinates and full imported curves, even when the illustrative model is selected. Clear this site's browser data to remove the draft. Downloaded files require separate deletion. |
| Export a project, report, graph, 3MF, STL or manufacturing ZIP | The browser creates a local download. The ZIP includes a project, both mesh files and printer handoff instructions. The project can include the normalized source envelope, full imported CSV, objective, solver settings, metrics and results. The graph and STL reveal geometry. | Your computer retains the files. Subsequent sharing sends the included data to the recipients you choose. |
| Load the browser model | The site serves WebLLM. Hugging Face and its delivery network serve the model. GitHub serves the pinned compiler. Those hosts see ordinary connection metadata, such as an IP address and potentially the workbench origin. | Twelve integrity-checked files total about 291 MB. The site caches model files in IndexedDB. Disconnect releases GPU memory. Site data clearing removes the model cache and any saved project draft. |
| Ask the browser model for a proposal | A dedicated local worker receives the text and the parameters for the chosen task. Its asset fetch policy is closed after loading. | The conversation is reset after generation. Disconnect or cancel terminates the worker. There is no remote inference request or API key. |
| Use the PrusaSlicer bridge | Local Python passes the selected model and printer profile to the installed PrusaSlicer CLI. | The selected output file is written on the machine. The user controls any subsequent printer transfer. |
| Preview the sample AI proposal | The browser constructs and validates a bundled example. | No model request or credential. |
| Connect OpenAI | The browser calls this site's health endpoint without the API key or brief. It keeps the key in the tab's memory. | Connecting checks the relay's capabilities. It does not verify the provider credential or incur a model call. Disconnect or reload to clear the in-memory key. |
| Ask OpenAI for a proposal | The browser sends the key in the Authorization header to the same-origin relay. The relay uses it to authenticate to the fixed official OpenAI Responses endpoint. The payload includes the prompt, action and its validated context (geometry recipe or mechanical objective), plus the system instructions and output schema. | The application writes no prompt or key logs and requests `store: false`. The relay operator and provider process the request. Provider and hosting retention policies still apply. Each inference request can bill the supplied key. |
| Connect a local gateway and request a proposal | Connection checks the configured loopback gateway. Proposing sends the same compact design context and prompt to it. The gateway forwards the request according to its configured provider. | Ollama and compatible services can run entirely on-device. Check the service settings and gateway operator. A gateway configured for official OpenAI forwards the request to OpenAI and uses its server-side key. |

A geometry proposal includes dimensions, family, envelope type, cell pitch, solid fraction, gradient, end skins and quality. An optimization proposal includes the fixed coupon dimensions, mass, drop height, allowable stroke, force ceiling and soft-contact preference. It excludes mesh coordinates, STL bytes, CSV rows, filenames, project files, numerical results, material hashes and beam graphs. For a gateway request, the trimmed text is sent to the selected destination. For browser AI, the brief stays in the local worker. Review the brief and the design before pressing **Ask AI for a proposal**. The app validates the response as a parameter draft and waits for **Apply** before generating or optimizing a specimen.

A trust boundary exists at the site origin. The operator of a hosted relay receives any key submitted with a proposal. If that is unsuitable, run the included local application and a trusted local inference setup. Inspect any reverse-proxy or infrastructure logging before operating a relay for others.
